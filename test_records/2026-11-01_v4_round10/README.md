## 轮10 根因：推理配对间隔 ≠ 训练配对间隔（OOD）

权重本身没问题——离线探针用**存好的数据集帧**喂服务器，输出≈GT。问题在闭环配对：

- 训练时每对帧间隔 = 5Hz 采样的 0.2s（画面差小）；
- 闭环 /act 周期 ≈0.9–1.7s，若 prev 取"上一次发给模型的帧"，静止场景里
  两半画面**逐像素相同**（训练分布里只有帧 0 长这样）；场景有运动时间隔又
  是训练的 5 倍大。探针复现：t=10 时取 lag=4/5 → 机械臂已在爬行段，模型却
  复读接近段动作 `[0.03,0,-0.019,0,0.01,0,1.0]`（张爪冲）；lag=1 → 正确
  `[0.001,0,0.008,...,0.75]`（收爪）。空抓由此而来。

**修复（无需重训）**：桥接端相机 ~8Hz 环形缓冲 `deque(maxlen=8)`（每回调都追加，
早于 processing 闸门），发送时 prev 取时间戳最接近 `t_cur − 0.2s` 的帧。

## 轮10b 崩溃

`TypeError: sequence index must be integer, not 'slice'`——deque 不支持切片；
改为 `list(self._frame_ring)[:-1]`。注：崩前那一步动作是**正确的接近段 token**
（单帧回退路径），已侧面验证堆叠链路通。

## 轮10d–10l：空抓复现 → 真根因"幽灵步"，桥接加 topic 门控（同日）

（本节结论在 10k/10l 后修正过：先前把根因写成"预热位"，只是半对。）

- 10d/10e/10g（重启前）/10i（重启后）：动作管线正确（抓取窗口 chosen 逐条=GT），
  但闭合每次都把杯**推离/碰倒 → 空抓**。
- 第一层原因（必要不充分）：预置位 `[0,…,0]` ≠ 演示起点，GT f0→f1 含
  **joint2 0→0.493 翻肘**，首帧全额快跳带残余下垂 → 需 f1 预热位起手。
  但 10k **带预热位仍空抓**——"预热 2/2"是统计假象。
- **真根因=幽灵步**：桥接相机回调**无任何门控**，就绪即按 parameter 指令
  连续推理驱动；手动流程里 instruction topic 晚到 2~11s，期间跑了 ~10 步
  "隐形动作"。铁证（bridge10k.log）：10k 第一个"可见"动作 joint2 已从
  预热位 0.493 掉到 **0.993**、Gripper=0.030（闭合并半程下压）——正式回合
  第一步就是闭爪犁杯。10c/10j 只是 topic 恰好秒到（幽灵步≈0）才成功。
- **修复（代码级，已 colcon 重建）**：`vla_gazebo_bridge.py`
  1. `instruction` parameter 默认改 `''`；为空时 image_callback 直接 return（不驱动）；
  2. 收到 instruction topic 时**全量重置回合状态**（last_action/帧环/model_ptr/
     stall/nopro/prev_sign/agree/episode_frozen）——topic=干净回合起手，可重复触发。
  手动起桥接**不要再传 `-p instruction:=…`**，等 topic。launch 自启桥接照常带
  参数（演示流程不变），照旧拦截 pkill。
- 10l 验证（修复后首测）：预热位起手、0 幽灵步、动作 1 从
  `[0,0.493,…]` 精确出发 → **真抓取：提升 +5.6cm**（0.5125）→ 倾倒 P≈0.9rad
  → 尾段张爪释放（Gripper 0.040）→ EPISODE COMPLETE（48 步，全程 ESCAPE-GT/stall=0）。
  落杯不完美：释放时残留倾角，杯子**斜立 ~18°并滑 7cm**（z +9mm，未倒）——
  属模型放杯行为（释放相偏斜），与起手无关，为下一个打磨点。
- v4 抓取统计修正：正确协议（预热+门控）下 10l 1/1；旧流程 2/7（10c、10j 撞运气）。
- f1 预热位（慢发 time_from_start=3s + 张爪 + 静置）仍是每轮必做（与门控配套）；
  10j（当时以为的"修复验证轮"）实测数据：抓取提升 +5.07cm → 倾倒俯仰 39° →
  落回站立（z +0.35mm、倾角≈1°）、最长复读 7、stall/ESCAPE-GT 全零——现确认
  其成功另因 topic 秒达、幽灵步≈0。
- 附带环境教训（重启后新 gz-sim 11.10.2 实例连炸 2 次，SIGABRT=boost
  shared_ptr 空断言，都发生在杯子被碰倒/指间挤压期间）：
  1. world 加载后先静置 ≥75s 再传送，否则物理弹跳会把底盘甩出（yaw 1.57→1.91），
     且需二次传送；2. 传送归位后**不再动底盘**，臂只走关节轨迹；
  3. 自启桥接拦截（0.3s 轮询 pkill）三连成功、0 动作泄漏。

## 轮10m–10q：夹爪早闭三级门控 → 完整冷重启验证通过（用户实况指出根因）

- 10m：topic 门控修好后**又空抓**。动作管线与 10l 逐条相同（raw/chosen/ptr/角度
  全对应），败在接触时机：模型第 1 步就吐 grip 0.75（GT f0~f7 应张爪 1.0），
  杯在第 2~4 步被 0.030 的指尖推离 +2~3cm。→ 加帧门控 `grip_open_until_ptr=8`
  （ptr<8 强制张满）。注意首次起桥接因缺 `declare_parameter` 崩一次，补齐重建。
- 10n：帧门控下**仍空抓**——放行闭合时 IK 解让指尖还在杯沿上方，杯子又被推前
  ~3cm。**用户实况复盘点破**："夹爪还没把杯子完全夹中间就闭合，杯子被往前推"。
  → 升级为**闭合深度门控** `grip_close_z_margin=0.02`：EE z ≤ GT f8 闭合帧
  高度+2cm（本场景阈值 0.241）才放行闭爪，放行后锁存不回张；回合重置清锁存。
- 10o（修复后）：**v4 历轮最干净**——提升 +5.5cm（0.5120）→ 倾倒俯仰 49.7° →
  张爪释放 → 杯子**站立**回桌（z +0.5mm、倾角 1.5°、位移仅 1.5cm），57 步，
  ESCAPE-GT/stall/Traceback 全 0，gzserver 存活，全程 ~76s。
- 10p：换**全新冷实例**跑 10o 同款配置，两级门控下仍空抓——闭爪那步 EE z 已是
  0.19 杯底限位（模型张爪指令拖到多步后才自己说闭），一闭合就把杯推离 +2cm。
  → 加**到位即捏**：深度达标当步强制 `min(cmd, 0.75)`，不再等模型。
- 10q（完整冷重启流程首测，用户要求"关了重开跑一次"）：清场→全新 launch→
  0.3s 拦截自启桥接（0 泄漏）→静置 75s→归位双测一致→预热→门控 0 幽灵步起手：
  **提升 +5.39cm → 倾倒 46.2° → 落回站立**（z +0.4mm、y 差 2.7mm、倾角 0.8°），
  57 步、零 ESCAPE-GT/stall/Traceback、gz 存活、底盘反冲仅 7mm——历轮最好落杯。
- v4 抓取终版统计：正确流程（预热+topic 门控）六轮 10l~10q = **3/6**
  （10l/10o/10q 成；10m/10n/10p 皆败于其后逐级修复的早闭路径）；
  最终三级门控代码形态 **1/1**（10q）；旧流程 2/7。样本仍少，结论以
  "逐级修因、每因一证"为准，非成功率。
- **复现配方（三件套，缺一翻车）**：
  1. `-p stack_frames:=true` + 环形缓冲配对（§轮10 根因）；
  2. 起桥接前 f1 预热位慢发+张爪+静置 ≥15s；世界新载先静置 ≥75s 再传送底盘；
  3. 桥接**勿传** `-p instruction`（默认 ''），就绪 idle=0 后发
     `/vla_instruction` topic 起手；夹爪三级门控（帧门 ptr≥8 + 深度门 z≤0.241 +
     到位即捏 0.75）代码内置，参数走默认即可。
